# BioMapper Benchmark Results

This document collects the measured benchmark results for BioMapper's cross-namespace molecular entity resolution. The results fall into two groups that carry different weight for the preprint. The first is *validation*: on the structure-anchored and identifier-mapping tasks the field already considers solved, BioMapper reaches parity with the established tools and reproduces their accuracy across both the metabolite and the gene/protein arms, which confirms the harness measures what it claims to. The second is *differentiation*: on the two axes where the incumbent tools and language models struggle — reproducibility under identical inputs, and cross-database grounding of names to identifiers — BioMapper separates from the field. We report both, and we are explicit about which is which. The benchmarking landscape and the reusable datasets these results draw on are described in the companion [Competitor Benchmarking & Dataset Inventory](https://phwiki.phenoma.ai/doc/how-comparable-tools-benchmark-and-the-datasets-biomapper-can-reuse-P1iIDhnksL) note. All figures are internal calibration outputs read directly from pinned run artifacts; the provenance table at the end lists each run.

## Determinism versus large language models (Figure 4)

We compared BioMapper against four language models on a fixed 25-query held-out set (metabolite, gene, and protein names, including hard cases), running each query 25 times per model and 3 times for BioMapper. The question is reproducibility: given identical inputs, does the method return the same answer every time?

![Figure 4. Determinism of cross-namespace resolution.](assets/Fig4_determinism.png)

BioMapper is deterministic. Its outputs are byte-identical across repeats, and all 25 queries resolve to exactly one distinct answer (variance = 0). Every language model returns different answers across identical repeats, and does so even when explicitly configured to be deterministic. gpt-4o with a fixed seed and temperature = 0 returned non-identical answers on 11 of 25 queries, despite the seed parameter being marketed for reproducibility. Opus 4.8, a frontier model that exposes no temperature control at all, produced up to 21 distinct answers for a single query across 25 runs. Sonnet 4.6 at temperature = 0 varied on 3 of 25 queries, and qwen3-8b was both wrong and highly variable.

The claim here is determinism, not accuracy superiority. On this deliberately hard 25-query set BioMapper reaches 44% accuracy, on par with gpt-4o (44%) and Sonnet 4.6 (44%), below Opus 4.8 (48%), and far above qwen3-8b (0%). We state plainly that Opus edges BioMapper by four points on this set; the result is that BioMapper delivers perfect reproducibility at an accuracy comparable to the frontier models, not that it is more accurate. The 44% absolute level is low because the set is intentionally difficult; this is a determinism benchmark, not an accuracy benchmark.

*Figure 4. (a) Distribution of distinct answers per query across 25 identical repeats, binned by count. BioMapper resolves every query to a single answer; the language models return two or more distinct answers on a substantial fraction of queries, with Opus 4.8 reaching 21 distinct answers on one query. (b) Accuracy across the same repeats (mean, with min–max range where present). Conditions shown are the temperature = 0 or native "asked to be deterministic" settings; n = 25 queries, 25 repeats per language-model condition and 3 for BioMapper. ## Grounding accuracy versus retrieval-augmented language models (MetaBench)

The single external benchmark that supports a valid head-to-head against language models is the MetaBench Grounding set (Lu et al. 2025, arXiv:2510.14944): 1,000 cross-database metabolite mapping pairs on which the paper scored 25 language models. We ran BioMapper against the identical 1,000-pair file the baselines were scored on — the adapter refuses to run against any other file by pinning its SHA — so the comparison is on the same items under the same exact-match rule.

BioMapper resolves the correct identifier on 54.5% of the 1,000 pairs (545 correct). The paper's language models, scored on the same set, reach at most 0.87% without retrieval (the best of the 25 is Claude-sonnet-4; every model scores under 1%, because a closed-book model cannot recall rare database identifiers) and at most 40.93% when augmented with a live web-search API (the best is GPT-5). BioMapper therefore exceeds the best retrieval-augmented language model by 13.6 points, and the best closed-book model by roughly sixty-fold. The fair headline is the 54.5%-versus-40.93% comparison against retrieval-augmented models; the sixty-fold figure against closed-book models is real but is the weaker comparison, since the paper's own point is that closed-book recall of identifiers is near zero.

Two properties make the 54.5% a conservative floor rather than a favorable reading. First, the raw harness initially scored this run at 24.3%, because BioMapper emits prefixed CURIEs (`KEGG.COMPOUND:C…`) while the gold answers are bare identifiers (`C…`), so all 400 KEGG-target rows failed on a prefix mismatch; normalizing that representational difference to match the basis the language models were scored on — not a change to BioMapper's predictions — recovers the true 54.5%. This normalization now lives in the harness scorer itself (a `KEGG.COMPOUND`↔`KEGG` namespace alias), and re-scoring the persisted predictions with the corrected scorer reproduces 545 of 1,000 exactly (KEGG 302/400, HMDB 86/400, CHEBI 157/200), so the headline is the harness's own output rather than a hand-computed correction. *(Verified 2026-07-24; scorer fix on branch `chore/scorer-rerun-structure-oracle`, still to merge to `dev`.)* Second, the 54.5% already absorbs a genuine coverage gap: the 200 pairs whose source is a bare KEGG compound number score zero, because those identifiers correspond to no queryable node in the knowledge graph. BioMapper wins the aggregate while carrying that hole, so a knowledge graph with fuller KEGG-source coverage would only raise the figure.

This is the clearest differentiation result in the set. On the one task where a same-set language-model comparison exists — grounding names and identifiers across databases, the regime the field considers unsolved — a deterministic method beats the best retrieval-augmented frontier model.

## Structure-anchored metabolite resolution

On the structure-anchored regime, where a metabolite name is resolved to a molecular structure, the field's tools already perform well, and the purpose of these runs is to confirm BioMapper reaches the same level and that the harness scores it honestly. In every case we score the predicted structure against the dataset's own curated InChIKey, an oracle independent of BioMapper's resolver, and we hold that gold structure out of the name-only input.

We calibrated first on the 100 curated metabolites of Hajjar et al. 2026. BioMapper resolved a structure for all 100 and matched the correct connectivity on 81 (81% Top-1). This 81% is a strict lower bound: the 19 misses are dominated by charge and protonation state rather than wrong molecules — fatty acids resolved to their carboxylate anions, amino acids to protonated or zwitterionic forms — and five resolved to knowledge-graph nodes that carry no structure at all, so a charge-normalized oracle would place the figure near 90%. This number is not a head-to-head against the Hajjar tools: that paper is an identifier-to-identifier interoperability study whose reported 92–100% figures are round-trip consistency counts on identifier inputs, whereas BioMapper's 81% is measured on the strictly harder name-input regime the incumbent tools never ran. Accuracy is identical across the four requested target namespaces (ChEBI, HMDB, PubChem, KEGG), because BioMapper resolves each name to one canonical node regardless of the requested vocabulary, so we report a single number rather than a per-namespace breakdown.

We then ran the larger and cleaner RefMet reference set from the Metabolomics Workbench. Of its roughly 206,000 rows, 34,404 carry a curated InChIKey; we drew a reproducible structure-bearing subsample of 1,500 (seed 42) and scored the resolved structure against that InChIKey. BioMapper matched the correct connectivity on 89.4% (1,341 of 1,500), rising marginally to 89.5% under a charge-normalized oracle. The near-identical strict and charge-normalized figures indicate that on a well-curated reference set, protonation state accounts for very few of the misses.

We repeated the calibration on a real-cohort delivery: the 1,495 plasma metabolites annotated by Metabolon in the New England Centenarian Study (Monti et al. 2026). On the 796 metabolites that carry a gold InChIKey, BioMapper matched the correct connectivity on 76.4% (608 of 796), rising to 78.1% under charge normalization. This figure sits below the curated-set numbers because a real-cohort delivery is larger and messier than a hand-curated list, and the small charge-normalization lift indicates protonation state is a smaller share of the misses here than in the curated sets. Taken together, the three structure-anchored runs place BioMapper at parity with the field on the solved regime and confirm the metabolite arm end to end.

## Name-hit coverage versus MetaboliteAnnotator

MetaboliteAnnotator (Lu et al. 2026, J. Proteome Res.) is the closest published metabolite name-harmonization tool, and it reports a name-hit rate — the fraction of input metabolite names for which the tool produces a target-vocabulary identifier — across six MetaboLights studies in positive and negative ion mode. We ran BioMapper on the identical six studies (MTBLS12997, MTBLS13105, MTBLS12764, MTBLS11733, MTBLS12636, MTBLS13039) under the same protocol, counting a hit when BioMapper resolves a name to any of CHEBI, HMDB, PubChem, or KEGG, and scoring on the same unique-name-per-study denominators the paper uses.

BioMapper reaches a name-hit rate of 94.95% in positive mode (4,096 of 4,314 names) and 95.10% in negative mode (2,386 of 2,509), against MetaboliteAnnotator's reported 93.2% and 93.5%; MetaboAnalyst 6.0 and metaboliteIDmapping are the paper's two lower baselines. BioMapper is therefore at parity with — marginally ahead of — the strongest published tool on this coverage metric, in both ion modes. The negative denominator is 2,509 rather than the paper's 2,510 because our unique-name deduplication differs by a single curated name, an immaterial difference.

This is a coverage measure, not a correctness measure: a name-hit records that an identifier was produced, not that it matches the studies' own annotation. The secondary identifier-concordance against the MetaboLights submitters' deposited identifiers is low — 7.1% in positive mode and 21.6% in negative — which reflects that BioMapper resolves to CHEBI/HMDB/PubChem/KEGG while the studies deposited identifiers in other vocabularies, not that the resolved structures are wrong. We report the name-hit rate as the directly comparable number because it is the metric MetaboliteAnnotator reports, and we state the concordance limitation alongside it so the coverage figure is not read as an accuracy claim.

## Structure-grounded comparison against metLinkR

metLinkR (Patt et al. 2025, J. Proteome Res.) is the closest published tool to BioMapper: it automates cross-linking of metabolite identifiers across datasets for meta-analysis, built on RefMet and RaMP-DB. It reports agreement with a set of links manually curated by COMETS consortium experts, but it performs no InChIKey structural validation of those links. We ran BioMapper on the same five COMETS-curated datasets, taking each metabolite name as the only input and holding out the curator links, and scored it two complementary ways.

On the curator-agreement metric metLinkR reports, BioMapper links 83.3% of the 401 cross-dataset curator pairs (334 of 401), against metLinkR's published 85.3% — parity within two points on the metric the tool was built to optimize. The second measure is the one metLinkR cannot report: for each curator-linked pair, we resolve both BioMapper's chosen identifier and the curator's identifier to an InChIKey first block and test whether they agree structurally. The curator's identifier is resolved through PubChem's PUG-REST service, independent of the knowledge graph that resolved BioMapper's prediction, so the concordance is not a system marking its own homework; the sixteen pairs the external service could not resolve are held out as needs-verification rather than scored either way. On this independent structural test BioMapper reaches 84.5% concordance (549 of 650 scored pairs).

The result is a clean differentiation. BioMapper matches metLinkR's linking coverage while additionally certifying that the links are structurally correct against an independent oracle, a validation the incumbent does not perform; where a string-based link and the structure disagree, the structural test is what adjudicates.

## Clinical reference coverage: NIST SRM 1950

The NIST SRM 1950 pooled-plasma reference material is a clinical-fit set, and it exposes a real coverage boundary rather than a parity result. Of its 1,058 entries, 983 carry a structure; BioMapper matched the correct connectivity on 40.3% of those (396 of 983). The low figure is a lipid-coverage gap: SRM 1950 is lipid-heavy, and the knowledge graph's structural coverage of individual lipid species is thin, so the misses concentrate in the lipid classes rather than spreading evenly. We report the aggregate here as measured; the lipid gap it exposes is then characterized directly, name by name, against the LIPID MAPS Structure Database below. This result is consistent with the other coverage gaps we have found (see the gene/protein arm below) and is an honest boundary of the current knowledge graph, not a scoring artifact.

## Lipid name-to-structure coverage (LIPID MAPS)

The lipid gap SRM 1950 exposed is quantified directly against the LIPID MAPS Structure Database (LMSD; Liebisch et al. 2020), roughly 50,000 curated lipids each carrying a shorthand abbreviation, common and systematic names, and an InChIKey. We drew a reproducible 1,500-lipid subsample (seed 42) and scored the resolved structure against LMSD's own InChIKey, taking the lipid name as input and holding out the LM_IDs entirely so the knowledge graph cannot short-circuit the task through an identifier it already indexes.

The result splits sharply by the kind of name. On common and systematic lipid names BioMapper matched the correct connectivity on 51.6% (rising to 53.5% under a charge-normalized oracle); on lipid shorthand — the compact `TG 57:6` notation that dominates real lipidomics output — it matched only 5.4%. A blended figure (19.8% over the full 1,500) would obscure this, which is why the two regimes are reported separately: shorthand notation, not lipids in general, is the wall. The small charge-normalization lift on common names reflects lipids whose fixed-charge headgroups (a phosphocholine zwitterion, for instance) shift the InChIKey relative to the graph's neutral form; shorthand gains nothing from charge normalization because its misses are failures to infer the connectivity at all, not protonation-state differences. This turns the aggregate boundary SRM 1950 surfaced into a concrete, named capability gap: lipid shorthand resolution.

## Name disambiguation on ambiguous cross-database names (Pham)

Pham et al. 2019 documented that metabolite names are inconsistent or ambiguous across biochemical databases at rates reaching 83%, the failure mode BioMapper is built to confront but which no public benchmark packages as a scorable task. We reconstructed the ambiguous-name population from the current MetaNetX release (4.5), joining its cross-database synonym lists to an independent curated InChIKey per compound, and restricted the set to genuine disambiguation cases — names that map to two or more distinct structural referents (129,877 in total). Because that population is dominated by lipid-isomer nomenclature, which overlaps the LIPID MAPS benchmark above, we stratify and report the non-lipid names as the headline: the abbreviation and cross-class ambiguity Pham emphasized, where a name such as `tmp` resolves to thymidine, thiamine, or cyclic monophosphates. From the 16,643 ambiguous non-lipid names we drew a 1,500-name subsample (seed 42).

An ambiguous name has no single correct structure, so we do not score Top-1 identity; we score structural membership — whether BioMapper resolves the name to any one of its legitimate referents. On the non-lipid ambiguous set BioMapper lands on a valid referent for 41.7% of names (625 of 1,500); the lipid stratum, reported separately, is 5.9%. Two properties frame the number honestly. First, these are the hard cases by construction — every name carries at least two competing structures — so 41.7% measures the difficult tail, not general accuracy. Second, a Top-1 resolver cannot expose the ambiguity it resolves: the collapse diagnostic confirms BioMapper returns a single referent where the name legitimately spans several, a property of any single-answer mapper and the reason disambiguation, not resolution, is the open problem this set measures. The gold referent sets come from MetaNetX and are independently cross-checked against PubChem by name, which corroborates them on the resolvable cases but not perfectly — 102 disagreements against 887 agreements — so the gold itself carries some uncertainty on this deliberately messy slice, a caveat we state rather than hide.

## Gene and protein resolution

We extended the benchmark to the gene and protein arm using the HGNC reference set. Given a gene symbol, we asked BioMapper to resolve it to its cross-references, scoring by identifier equality against HGNC's own authoritative cross-references and holding the gold identifiers out of the input.

![Supplementary figure. Gene-symbol cross-reference resolution.](assets/FigS_gene_protein.png)

On a 1,500-symbol sample, BioMapper resolved the correct cross-reference for 96.3% of symbols overall, with per-namespace accuracy of 97.8% to NCBI Gene, 90.6% to UniProt, and 76.7% to Ensembl. Unlike the metabolite arm, the per-namespace breakdown is informative here, because the different target namespaces have genuinely different coverage in the knowledge graph. This validates the gene and protein arm end to end.

For identifier inputs, the correct measurement is a provided-identifier mode that maps the source identifier through the knowledge graph's equivalence expansion, rather than feeding a bare identifier to the name-resolution path (which fuzzy-matches it to unrelated entities and returns near-zero, as expected). In that mode, mapping NCBI Entrez gene identifiers to Ensembl reaches 99.2%, a clean same-task anchor on the identifier-mapping regime. The same mode surfaces a genuine gap in the opposite direction: mapping UniProt protein accessions to their genes returns zero, because the resolver returns the protein-level Ensembl identifier where the gold is the gene-level identifier — a real knowledge-graph coverage boundary that we report rather than paper over.

## Head-to-head against incumbent identifier-mapping tools

On the gene/protein identifier-mapping task we ran three established tools — bioDBnet, g:Convert, and the UniProt ID-mapping service — against the same HGNC gold set, scoring Top-1 identifier equality per target namespace and over the union of all three. The honest read is parity: BioMapper is competitive with the incumbents on this solved task, placing second of four on the union metric, at or slightly below the strongest tool per namespace.

| Tool | Ensembl | NCBI Gene | UniProtKB | Union |
|------|---------|-----------|-----------|-------|
| bioDBnet | 0.791 | 0.999 | 0.995 | 0.986 |
| **BioMapper** | 0.767 | 0.978 | 0.906 | 0.963 |
| g:Convert | 0.960 | 0.550 | 0.956 | 0.904 |
| UniProt ID-mapping | — | — | 0.937 | 0.398 |

An earlier version of this comparison reported BioMapper as the only tool strong across all three namespaces; that claim was withdrawn once we traced it to a scoring artifact on our side. bioDBnet returns multiple values in a `//`-delimited field that our client split on a different separator, and g:Convert returns version-suffixed accessions our scorer did not strip, so both tools' UniProtKB scores were spuriously near zero. Correcting the parsing lifted g:Convert's UniProtKB from 0.000 to 0.956 and bioDBnet's from 0.061 to 0.995. We verified the correction was not one-sided: BioMapper's own predictions carry version suffixes too, but it co-emits the unversioned form on every one of the 637 affected rows, so its 0.906 is genuine and not artificially suppressed. The corrected picture is that bioDBnet is strong across all three namespaces and BioMapper is at parity or marginally behind the incumbents per namespace — which is the expected and honest outcome on a task the field already solves, and it locates BioMapper's advantage on the harder grounding task and the determinism axis rather than on this lookup.

## Case study: harmonizing a Metabolon MS1 dataset

As an end-to-end demonstration on a real delivery, we resolved a 2,710-feature Metabolon annotation panel with BioMapper and compared its assignments, feature by feature, against the panel's reference identifiers. We report the MS1 slice — the 152 features carried at the MS1 match level — because these are the well-covered features on which a like-for-like, shared-namespace comparison is possible; the MS2 and curation-level features frequently lack a shared-namespace identifier on one side or the other, which is why panel-wide comparability is far lower (1,001 of 2,710, 36.9%). The reference in this run is a RefMet-coverage panel rather than Metabolon's own curated compound identifications, and the agreement reported here is pre-adjudication; both boundaries are stated explicitly below.

Of the 152 MS1 features, 127 are comparable in the sense that BioMapper and the reference both assign an identifier in a shared namespace (127/152 = 83.6%). Among these comparable features, BioMapper agrees with the reference on every shared namespace for 84.3% and on at least one for 95.3%. Resolved by namespace, agreement is high everywhere except ChEBI: InChIKey 98.4%, KEGG 98.8%, HMDB 98.2%, and LIPID MAPS 100%, against 84.9% for ChEBI (107/126). The ChEBI dip is the same representational effect seen throughout the metabolite arm — charge state and stereochemistry, not a wrong molecule — rather than a resolution error, and the ~5% of comparable features on which no shared namespace agrees is the set a downstream adjudication step would triage.

Two boundaries bound this case study. First, the reference is a RefMet-coverage panel, not Metabolon's curated compound assignments; a concordance against the *curated* delivery, together with the per-compound rollup that would let agreement be reported per named compound rather than per feature, requires the original Metabolon client delivery, which was not available for this run and is left to future work. Second, the figures are pre-adjudication: they measure raw BioMapper-versus-reference agreement, before any tie-breaking of the disagreements. Reported honestly on the reference available, BioMapper reproduces the panel's MS1 identifications on roughly 84% of comparable features under an all-namespace criterion (95% under any-namespace), with the residual concentrated in ChEBI representational variants rather than in misidentification.
